# phone-VibeKey 使用手册

> 版本 0.7.1 · 适用 Windows 10/11 + 手机浏览器
> 一句话定位：**手机就是你的 VibeKey**——把手机当成电脑的语音键，说出来的字直接落在 PC 光标处，回车即交给 Agent。
> 本文回答两个问题：**它适合/不适合用在什么场景**，以及**在什么样的网络环境里能跑、跑不动时怎么修**。

---

## 一、它到底是什么

手机浏览器打开一个页面 → 点输入框 → 用**手机输入法自带的语音**（微信输入法、豆包、讯飞、Gboard……）说话 → 文字在手机上实时出现 → 松手后 **2 秒内**这段文字出现在**电脑当前光标处**。

三个关键点，决定了它后面所有的能力边界：

1. **不做语音识别**。识别交给手机上已有的输入法。所以识别质量 = 你输入法的质量，本软件不联网、不调云端 ASR、不处理音频。
2. **不做手机 App**。手机端是一个网页，加到主屏幕后像个 App。所以没有后台常驻、没有权限申请、没有应用商店审核。
3. **不做公网中转**。手机和电脑在同一个局域网内直连，不走服务器。所以没有月费，也没有跨公网能力。

## 二、使用范围

### 2.1 适合的场景

| 场景 | 说明 | 典型体验 |
|---|---|---|
| 电脑上打长段中文 | 微信/QQ/钉钉聊天、写周报、写文档、填表单 | 说话速度 ≈ 400 字/分钟，是打字的 3–5 倍 |
| 电脑前但手不想离开键盘区 | 手机放桌上，按住麦克风说完，文字直接落到电脑光标 | 不用切窗口、不用复制粘贴 |
| 临时口述、边想边说 | 输入法边说边上屏，你能看到它听错没有 | 说完即可发，不用二次确认 |
| 多句连续口述 | 连续说几句，每句各落一段，不重影不粘连 | 句间停顿 1 秒内自动续写 |
| 只想敲个回车/清空 | 手机页面上的「回车 ⏎」「清空电脑输入框」 | 远程按一次 Enter / 删掉刚落的字 |

### 2.2 不适合的场景（重要，先看这里）

| 场景 | 为什么不行 |
|---|---|
| **需要跨公网**（手机用流量、在公司和家里的电脑之间） | 设计上只做局域网直连，没有中转服务器、没有 TLS、没有穿透。手机不在同一个 WiFi 里就连不上。 |
| **管理员权限窗口**（任务管理器、部分安装程序、UAC 弹窗） | Windows UIPI 机制：普通权限进程不能向高权限窗口发按键。除非整个软件以管理员运行，本项目不做。 |
| **游戏 / 带反作弊的程序 / 远程桌面窗口** | 反作弊会拦截模拟输入；RDP 里注入的是本地会话而非远程会话。 |
| **锁屏 / 登录界面** | 安全桌面隔离，任何用户态程序都注入不进去。 |
| **完全没装输入法语音的手机** | 本软件不提供语音，识别来自你的输入法。输入法没有语音键就用不了。 |
| **macOS / Linux 电脑** | PC 端是 Windows 专用（ctypes + SendInput + 剪贴板 API）。 |
| **要求"专业级"识别准确率、专业术语、方言** | 取决于输入法。微信输入法/豆包的中文识别已经很好，但做不到 Whisper 级别的大模型准确率。 |

### 2.3 能粘贴进哪些程序

按兼容性从高到低：

| 目标程序 | 支持 | 说明 |
|---|---|---|
| 微信 / QQ / 钉钉 / 飞书 聊天框 | ✅ 完全支持 | 最常用，实测稳定 |
| 记事本 / 写字板 / Word / Excel / PPT | ✅ 完全支持 | 中文、标点、emoji 都正常 |
| Chrome / Edge / Firefox 里的输入框 | ✅ 完全支持 | 网页表单、搜索框、聊天 |
| VS Code / Sublime / 各种编辑器 | ✅ 支持 | 编辑器里 Ctrl+V 是粘贴，正常 |
| Windows Terminal / cmd / PowerShell | ⚠️ 多数可用 | 传统控制台对 Ctrl+V 支持不一致：Windows Terminal 正常；旧 conhost 可能只认右键粘贴。 |
| 需要管理员权限的窗口 | ❌ 不支持 | 见 2.2 |

### 2.4 对电脑和手机的要求

- **电脑**：Windows 10 / 11，Python 3.10+（开发用 3.14），能装 `aiohttp`/`pystray`/`pillow`/`qrcode` 四个包；有托盘（任务栏右下角）。
- **手机**：任意能装 Chrome / Edge / Safari / 夸克 / 微信内置浏览器的手机；**必须装有语音输入功能的输入法**（微信输入法、豆包输入法、讯飞输入法等）。iOS 与 Android 都行。
- **网络**：手机与电脑能互相访问（见第三节）。

## 三、网络环境完整说明

### 3.1 一句话原理

**电脑是服务端，手机是客户端。** 电脑上跑一个小服务，监听 TCP 8765；手机浏览器连上去，发 WebSocket 消息；电脑收到文字后用「剪贴板 + Ctrl+V」把它粘贴到当前光标处。

```
   手机 (192.168.31.216)              电脑 (192.168.1.3)
   ┌──────────────────┐              ┌───────────────────────────┐
   │  浏览器页面       │  WebSocket   │  agent.py  监听 :8765      │
   │  输入法语音 → 文字 │ ───────────▶ │  ├─ 去重 / 增量 / 退格      │
   │  （手机上屏）      │   局域网     │  └─ inject.py               │
   └──────────────────┘              │      剪贴板 + SendInput    │
                                      │            ↓               │
                                      │      当前焦点窗口的光标处   │
                                      └───────────────────────────┘
```

### 3.2 支持的网络拓扑

| 拓扑 | 是否可用 | 说明 |
|---|---|---|
| 手机与电脑连**同一个路由器**（最常见） | ✅ | 同一网段，直连。 |
| 手机连路由器 A，电脑连路由器 B，**B 在 A 的 LAN 口**（电脑在"上游"） | ✅（本项目实测环境） | 见 3.4：手机经 A 的 NAT 能访问 B 网段里的电脑。 |
| 手机连路由器 A，电脑连 B，**B 通过 A 的 WAN 口**（电脑在"下游"） | ❌ | 上游设备无法主动访问解析到下游 NAT 内部的设备。 |
| 两台设备连不同的 Wi-Fi（不同 SSID、不同网段、都做了隔离） | ❌ 通常不行 | 家用路由器默认开启"AP 隔离"或不互通。 |
| 企业网 / 校园网 / 公共 Wi-Fi | ⚠️ 视情况 | 常开启客户端隔离（client isolation），手机与电脑互相不可见。 |
| 电脑用有线、手机用 WiFi，但**同属一个路由器** | ✅ | 有线/WiFi 只是接入方式，同属一个二层网络就能通。 |
| 开 VPN / 代理软件 | ⚠️ 可能坏 | 全局代理会劫持 WebSocket 或改路由表；关掉即可。 |

### 3.3 判断你的网络能不能用（30 秒自检）

在**电脑**上：

```powershell
# 1. 服务起来了吗？看有没有 LISTENING
netstat -ano | findstr :8765

# 2. 本机地址是多少（手机要连的就是这个）
ipconfig | findstr IPv4
```

在**手机**上：浏览器打开 `http://<电脑IP>:8765`，例如 `http://192.168.1.3:8765`。

- 能打开页面 → 网络通，继续扫码配对即可。
- 打不开 → 按 3.6 的清单排查，**90% 是 Windows 防火墙**。

### 3.4 为什么手机能连电脑、电脑连不了手机（实测结论）

本项目开发环境的真实拓扑：

```
手机 192.168.31.216 ──WiFi──▶ 路由器A(192.168.31.1) ──WAN:192.168.1.2──▶ 路由器B(192.168.1.1) ──▶ 电脑 192.168.1.3
```

- 手机访问电脑时，路由器 A 做了一次 **SNAT**，电脑看到的来源地址永远是 `192.168.1.2`（路由器 A 的 WAN 口）。
- 电脑的 `route print` 里**没有**去往 `192.168.31.0/24` 的路由，所以电脑无法主动连手机。
- 因此：**必须是电脑当服务端、手机当客户端**。这也是为什么本软件不做"电脑主动推送"、不需要在手机上开放任何端口。
- 副产品：电脑上**无法按来源 IP 区分不同手机**（永远是同一个 NAT 地址），所以身份识别靠 URL 里的 `?t=<token>`，而不是 IP 白名单。

### 3.5 端口、防火墙与多网卡

- **端口**：默认 `8765`（TCP）。可在 `%APPDATA%\phone-VibeKey\config.json` 改 `port`；改完需要重新放行防火墙（托盘菜单「修复手机连不上（防火墙）」）。
- **防火墙**：托盘菜单 →「修复手机连不上（防火墙）」会以管理员权限添加一条**按程序放行**的入站规则（`phone-VibeKey`，覆盖 专用/域/公用 三种网络配置文件）。规则按 `python.exe` 放行，不是按端口，所以改端口不需要再点一次。
- **多网卡**：电脑如果有多个地址（有线 + WiFi + 虚拟网卡 + Tailscale），托盘菜单「复制手机地址」给的是**主地址**，二维码里同时嵌了所有候选地址（`&e=` 参数）。手机连不上主地址时会自动换下一个；全都不行时，点页面上的「没连上电脑 · 点这里手动填地址」手填 IP。
- **公用网络**：Windows 把新网络识别为"公用"时会收紧防火墙。本软件的规则覆盖三种 profile，所以插到新的网线也不怕。

### 3.6 连不上？按这个顺序查

1. **服务在跑吗**：任务栏右下角有没有托盘图标（蓝底麦克风）。没有就双击 `pc\启动.cmd`。
2. **端口在听吗**：`netstat -ano | findstr :8765` 有 `LISTENING` 才对。
3. **本机能开吗**：电脑浏览器打开 `http://127.0.0.1:8765`，能开说明服务正常。
4. **同网段能开吗**：手机浏览器打开 `http://<电脑IP>:8765`。
   - 打不开 → 防火墙。点托盘「修复手机连不上（防火墙）」，然后重试。
   - 还是打不开 → 手机和电脑不在同一张网（AP 隔离 / 不同网段无路由）。换同一个路由器的 WiFi 再试。
5. **能开页面但一直"未连接"**：说明 `/` 通但 WebSocket 不通，通常是杀毒软件/代理拦了 WS。关掉代理，或换一个浏览器。
6. **连接成功但打字不出现在电脑上**：
   - 电脑光标是不是在**可输入的输入框**里？点在桌面/文件夹空白处时，文字只会放进剪贴板，页面会提示「电脑上没有输入框 · 已放进剪贴板」。
   - 目标窗口是不是管理员权限？见 2.2。
   - 试试先手动 Ctrl+V 一次，确认剪贴板里有字。
7. **有时灵有时不灵**：多半是焦点在发送的瞬间变了（比如消息弹窗抢焦点）。发送失败时文字会自动保留回手机输入框，直接再发一次即可。

### 3.7 延迟是怎么花的（实测分解）

一句话：**说话 → 电脑上出现文字**，典型 1.5–2.5 秒（说长句时人感觉不到延迟，因为文字边打边出）。

| 环节 | 耗时 | 说明 |
|---|---|---|
| 输入法识别并上屏 | 300–800 ms | 你输入法的能力，本软件不参与 |
| 判断"这句话说完了" | 700–1200 ms | 自适应静默窗口：按你最近 8 次出字节奏算，最长 1.2 s |
| 手机 → 电脑（局域网 WS） | 5–20 ms | 同一路由器内，一次小 JSON |
| 电脑写入剪贴板 + Ctrl+V | 40 + 220 ms | 粘贴后留 260 ms 再把剪贴板还回去 |
| **合计** | **约 1.1–2.3 s** | 松手到电脑落字的整体感知 |

标点符号不会自动加（输入法自己加的标点会保留）。

### 3.8 手机不在家怎么办

**不支持。** 没有公网中转、没有 TLS、没有穿透。如果以后要做，最小改动是加一层中继服务（VPS + WebSocket 转发）或引入 Tailscale 之类的组网，两者都需要额外部署与配置。

## 四、使用流程

### 首次配对（一次）

1. 双击 `pc\启动.cmd`。托盘出现图标，屏幕弹出二维码。
2. 手机「扫一扫」（微信/系统相机都行）扫这个二维码 → 浏览器打开页面。
3. 页面 title 下方显示 `192.168.1.3` 和绿色「已连接」。
4. 手机浏览器菜单 →「添加到主屏幕」，以后从桌面图标进。

配对信息（`?t=token`）会记住在浏览器 localStorage，以后不用再扫。

### 日常使用

1. 点开手机桌面上的 phone-VibeKey 图标 → 输入框自动聚焦、键盘弹出。
2. 按住输入法的麦克风说话，边说边看字。
3. 松手 → 字自动出现在电脑光标处，页面顶部显示「已送达 · N 字」。
4. 想敲回车：按输入法的回车/换行键，或点页面「回车 ⏎」。
5. 想撤回刚落的字：点「清空电脑输入框」（按记录的字数逐字退格）。

### 换电脑 / 换网络

- 换了电脑：新电脑跑 `启动.cmd` 扫码即可。
- 换了路由器：手机自动在二维码里的候选地址间切换；都失效时点页面「点这里手动填地址」。

## 五、隐私与安全

- **不碰音频**：本软件不采集、不发送、不存储任何语音。语音识别在手机输入法内部完成，你可能需要知道你的输入法是否把音频传上云（那是输入法的事，与本软件无关）。
- **文字不出局域网**：文字只发到同网段的电脑，走明文 WebSocket。
- **token 在 URL 里**：`?t=xxxx` 是访问凭据（32 位十六进制）。同一局域网内的人如果知道了这个 URL 就能往你电脑打字。不要把 URL 发给别人，不要在公共 WiFi 下使用。
- **不监听公网**：服务只监听本机，但如果你把 8765 端口在路由器上做了端口映射，请立刻撤销。
- **日志**：`%APPDATA%\phone-VibeKey\agent.log` 只在崩溃时写。

## 六、已知限制

1. 只支持 Windows。macOS/Linux 需要另写注入层。
2. 不支持跨公网。
3. 不支持管理员权限窗口、游戏、远程桌面。
4. 中文以外：英文、日文、emoji 走剪贴板都能过；但识别准确率取决于输入法。
5. 焦点判断有边界：桌面/任务栏/资源管理器这类"确定无输入框"的窗口会被识别并降级为"只进剪贴板"；但微信、浏览器、Office 这类复合窗口无法可靠判断内部是否有输入框，仍按正常粘贴处理。
6. 没有版本回滚、没有账号、没有云端历史（历史只存在手机浏览器本地，最多 10 条）。
